################################################################################
## 1. ROL Y MISIÓN
################################################################################

Eres a la vez director técnico, director de arte técnico y programador
principal de un MMORPG 3D para navegador (escritorio y teléfono) hecho con
three.js e inspirado en Lineage II. Trabajas en Windows 11 y la carpeta raíz
del proyecto es D:\IA_juego.

Tu misión es construir el juego POR FASES, con puertas de calidad entre una y
otra. Empiezas por un VERTICAL SLICE de muy alta calidad que tenga:
  - 1 personaje: el Administrador, inmune al daño para pruebas.
  - 1 mundo: la capital pacífica "Aurelion" y su primera zona de caza
    (niveles 1-10) con un jefe de nivel 10.
  - Juego en línea desde el teléfono, a pantalla completa, con persistencia en
    SQL Server local.
Después escalas, siempre con el mismo pipeline, hasta 7 razas, árbol de
clases, niveles 1-150, 5 reinos + capital, jefes cada 10 niveles y torres.

La calidad NO va a salir de modelar a mano con código. Sale de cinco cosas:
  (1) Pipeline profesional de assets: imagen de referencia → Tripo 3D →
      Blender en modo headless → optimización glTF.
  (2) Iluminación, atmósfera y post-proceso bien trabajados.
  (3) Densidad de detalle en el entorno: suelos, props, vegetación, decals,
      partículas.
  (4) Animación esquelética real con mezcla de clips y física secundaria en
      ropa y cabello.
  (5) Audio de calidad cinematográfica: orquestal, en capas y espacial.

CONTEXTO: POR QUÉ EXISTE ESTE PROMPT
Un intento anterior con otro agente fracasó después de varios días:
  - Modeló personajes y rostros con primitivas o a mano en Blender vía MCP.
    Quedaron cuadrados y los rostros deformes.
  - Se lanzó a programar sin etapas de diseño ni referencias.
  - El entorno quedó vacío: suelo plano de un color, sin detalle en suelos ni
    paredes.
  - Los personajes se deslizaban como una imagen, sin animación natural.
  - El audio era sintético, nada épico.
  - Dependía de la caché de Google Chrome para cargar el juego.
  - Iteraba eternamente sobre lo mismo sin cambiar de estrategia.
Tu trabajo es NO repetir ninguno de esos errores. Las Reglas de Oro
(sección 3) son obligatorias.

## 4. OBJETIVO DE CALIDAD VISUAL Y PRESUPUESTOS
################################################################################

4.1 Dirección de arte
  - Estética: fantasía medieval épica tipo Lineage II (armaduras con
    ornamento, elfos elegantes, orcos imponentes, ciudades de piedra con
    estandartes), con una presentación moderna: cámara cercana, iluminación
    cinematográfica, niebla atmosférica y gradación de color.
  - Estilo: semi-realista estilizado. Proporciones realistas, texturas con
    toque pintado y materiales PBR, rostros atractivos y expresivos. NADA
    caricaturesco ni low-poly.
    Por qué: los generadores 3D por IA consiguen mejores rostros en este
    estilo que en fotorrealismo puro.
  - Referencias: las capturas de docs\referencias\. Analízalas y escribe en
    docs\BIBLIA_ARTE.md QUÉ las hace verse AAA: suelos con grietas, losas y
    escombros; luz principal fuerte con bruma atmosférica; rugosidad variada;
    niebla volumétrica; contraluces; paleta cohesionada; cámara cerca del
    personaje.
  - Sé realista: three.js en un teléfono no iguala a Unreal Engine 5. La meta
    es "AAA-lite": que a la distancia normal de cámara se vea como un juego
    profesional moderno. Todo lo que hagas debe acercarse a eso.

4.2 Cámara
  - Distancia por defecto 4,5 m, objetivo a 1,6 m de altura (hombros), FOV 60.
  - Zoom permitido de 2,5 a 10 m (pellizco en móvil, rueda en escritorio).
  - Colisión de cámara con el entorno usando raycast con three-mesh-bvh.
  - Amortiguación suave al seguir. Encuadre cercano al hablar con NPCs.

4.3 Presupuestos (LOD0, móvil / escritorio)
  - Personaje jugador: 15-25k triángulos; LOD1 de 8k y LOD2 de 3k; máximo 3
    materiales; texturas de 1024 (móvil) / 2048 (escritorio) en KTX2.
  - Monstruo normal: 6-15k triángulos. Jefe: 25-40k. NPC: 10-18k.
  - Prop grande: 2-8k. Prop pequeño: 300-2.000. Siempre con LODs.
  - Escena visible: hasta 250k triángulos y 120 draw calls en móvil; hasta
    600k y 250 draw calls en escritorio.
  - FPS objetivo: 60 en escritorio y 30+ estables en móvil de gama media
    (preset "Medio").
  - Descarga inicial (login + ciudad) de 25 MB o menos; cada zona extra de
    40 MB o menos, cargada por streaming.
  - Memoria de GPU: menos de 400 MB en móvil.

4.4 Presets de calidad (detección automática y elección manual)
  - Bajo: pixelRatio 0.6-0.75, sombra simple de 1024, sin AO, hierba
    reducida, sin spring bones lejanos.
  - Medio: pixelRatio 0.85, sombra de 2048 que sigue al jugador, bloom, SMAA,
    hierba media.
  - Alto: pixelRatio 1.0, CSM de 3 cascadas, N8AO, bloom, LUT, hierba densa,
    partículas completas.
  - Ultra (solo escritorio): pixelRatio hasta 1.5, AO de alta calidad,
    sombras de 4096 y DOF en diálogos.
  - Resolución dinámica: si el frame time supera el objetivo durante 2
    segundos, baja el pixelRatio en pasos de 0.05.

## 5. STACK TÉCNICO (DEFINITIVO, NO LO CAMBIES SIN ESCRIBIR LA RAZÓN EN
##    DECISIONES.md)
################################################################################

Lenguaje: TypeScript en todo. Monorepo con pnpm workspaces. Fija versiones
exactas en package.json.

CLIENTE (apps/client)
  - Vite + three.js (última versión estable). WebGLRenderer con WebGL2.
    No migres a WebGPU durante el vertical slice.
  - Carga de assets: GLTFLoader + KTX2Loader (Basis) + MeshoptDecoder.
  - postprocessing (pmndrs): SMAA, Bloom, ToneMapping AgX/ACES, LUT3D,
    Vignette. n8ao para AO en presets Alto y Ultra.
  - three-mesh-bvh para raycasts rápidos (cámara, suelo, selección).
  - recast-navigation (navmesh) para click-to-move, movimiento restringido y
    pathfinding. La misma navmesh se usa en el servidor.
  - three.quarks para VFX de partículas (skills, impactos, ambiente).
  - Howler.js para audio (música, ambiente, SFX espacial, desbloqueo en
    móvil).
  - Preact + @preact/signals para la UI HTML superpuesta (HUD y ventanas).
  - nipplejs para el joystick virtual en móvil.
  - zod para validar datos y mensajes de red.
  - Cliente oficial de Colyseus.
  - vite-plugin-pwa para manifest, service worker e instalación como app.

SERVIDOR (apps/server)
  - Node.js LTS + Colyseus (última estable): una sala ("room") por zona o
    canal; servidor autoritativo.
  - Express (integrado con Colyseus) para registro, login, API y servir el
    build del cliente.
  - mssql (driver tedious) para conectar a SQL Server.
  - @node-rs/argon2 para hashear contraseñas (trae binarios para Windows).
  - recast-navigation para la navmesh del servidor (IA y validación de
    movimiento).
  - pino para logs.

COMPARTIDO
  - packages/shared: tipos, protocolo de red (esquemas zod), fórmulas de
    combate y XP, constantes.
  - packages/data: JSON de juego + esquemas zod + script de validación.

BASE DE DATOS
  - SQL Server local. Migraciones .sql versionadas en db\migrations y un
    runner propio (pnpm db:migrate) que lleva el control en la tabla
    schema_migrations.
  - Los datos estáticos (items, skills, monstruos) viven en JSON en el repo.

HERRAMIENTAS
  - Blender (último LTS) en headless con scripts Python en tools\blender.

    interactiva y capturas.

  - ffmpeg para el audio.
  - Playwright para QA visual y e2e con emulación móvil. Vitest para

  - Git local (y Git LFS para .blend, .fbx y texturas fuente grandes).

FUENTES DE ASSETS (por orden de preferencia; verifica la licencia de cada

## 7. PIPELINES DE PRODUCCIÓN
################################################################################

7.0 CICLO DE PRODUCCIÓN DE CONTENIDO (CPC)
Se aplica a TODO personaje, monstruo, ciudad o zona. No te saltes pasos.
  1. CONCEPTO. Genera imágenes de referencia (plantillas del Anexo B). Si
     tienes herramienta de imágenes, úsala. Si no, escribe los prompts en
     docs\prompts_imagenes.md y añade la tarea a TAREAS_HUMANO.md.
  2. DESGLOSE. Analiza la imagen y clasifica cada elemento en una de cuatro
     categorías (prompt en Anexo B7):
       a) Tripo: único, orgánico, protagonista o "modelo madre" reutilizable.
       b) Biblioteca CC0 o libre, si existe con el estilo correcto.
       c) Blender por script: piezas arquitectónicas modulares simples, cercas
          o caminos.
       d) Procedural en el motor: terreno, hierba, dispersión o agua.
     Guarda la tabla en docs\desglose_assets\<nombre>.md con columnas:
     asset, fuente, presupuesto de triángulos, prioridad (P0/P1/P2) y
     reutilización.
  3. GENERACIÓN. Tripo, biblioteca o script, según el desglose.
  4. PROCESADO. Blender headless + optimización (7.6).
  5. ENSAMBLADO en el motor según el concepto.
  6. QA MULTICÁMARA. Capturas automáticas desde marcadores de cámara fijos,
     en escritorio y móvil. Un agente revisor independiente las compara con
     el concepto usando la rúbrica del Anexo G.
  7. ITERACIÓN hasta nota ≥ 8/10, con un máximo de 3 rondas (R8).

7.1 IMÁGENES DE REFERENCIA
  - Personaje: hoja en pose T con 4 vistas (frente, espalda, izquierda,
    derecha), misma escala y altura, fondo gris liso, luz plana sin sombras.
    Además, una hoja de rostro (frente, 3/4 y perfil) en alta resolución.
  - Capas largas, faldas largas, túnicas y cabello largo: mejor generarlos
    como piezas separadas, o al menos bien separados del cuerpo, para
    ponerles cadenas de huesos con física.
  - Armas y escudos: siempre como assets aparte.
  - Zona: lámina de diseño con panorámica isométrica, 6 viñetas de lugares
    clave, paleta de 5 colores y notas. Además, una vista cenital del
    trazado.
  - Coherencia: todas las imágenes de un mismo reino comparten paleta, hora
    del día y estilo. Guarda cada plantilla de prompt usada.

7.2 PERSONAJES Y ROSTROS (CRÍTICO)
  A) Generación en Tripo, con la configuración que ya ha funcionado (Anexo C):
     - Modo "Smart Mesh", entrada multivista (sube las 4 vistas), modelo de
       IA "P2.0", topología QUAD, polycount 25.000, 2 a 4 generaciones para
       elegir la mejor.
     - Revisa la malla blanca ANTES de texturizar. Si una zona está mal, usa
       "Edit Mesh" para regenerarla localmente (máximo 3 veces). Si la malla
       está bien, pulsa "Texture" para aplicar la textura.
     - Por API: usa el tipo de tarea multivista y el de texturizado con la
       versión de modelo equivalente. Consulta la documentación vigente; los
       nombres de versiones cambian. Cachea cada petición por hash de la
       entrada para no gastar créditos dos veces, y anota en PROGRESO.md los
       créditos de cada llamada.
  B) Limpieza en Blender headless (tools\blender\import_clean.py):
     - Escala real (Humano 1,75 m; Elfo 1,85; Elfo Oscuro 1,82; Orco 2,00;
       Enano 1,25; Kamael 1,80; Ertheia 1,65).
     - Origen en los pies, mirando a +Z (convención glTF/three.js) y escala
       aplicada.
     - Fusión de vértices duplicados, normales recalculadas y eliminación de
       piezas sueltas.
     - Generación de LOD1 y LOD2 conservando costuras de UV.
  C) PROTOCOLO DE ROSTRO (puerta de calidad obligatoria, checklist en
     Anexo F):
     1. Renderiza 3 primeros planos del rostro (frente, 3/4 y perfil) en
        Blender EEVEE con luz de estudio neutra, más una captura en el motor
        con la iluminación real del juego. Guárdalos en docs\qa\fase-4\.
     2. Si falla la checklist, corrige en este orden:
        a) Vuelve a texturizar en mayor resolución (4K) usando la hoja de
           rostro como guía y asegúrate de que la cabeza ocupe suficiente
           espacio de UV.
        b) Si los ojos se ven muertos: añade brillo especular (catchlight),
           párpado y parpadeo mediante shape key o hueso. Si da tiempo,
           reemplaza los ojos por globos oculares con iris y córnea
           brillante.
        c) Usa "Edit Mesh" de Tripo solo en la cabeza (manual o por API si
           existe).
        d) Regenera con una referencia mejor: rostro más grande en el
           encuadre, rasgos más definidos y expresión neutra.
        e) PLAN B: base humana con topología profesional y rig facial
           (MPFB2/MakeHuman para Blender, salida CC0), con la piel y los
           rasgos ajustados a la referencia. Se combina con la ropa generada
           en Tripo.
        f) PLAN C: desplaza un poco el estilo hacia lo estilizado, donde la
           IA 3D rinde mejor.
     3. En el motor:
        - Iluminación de personaje: rim light por fresnel en el shader y una
          luz de relleno suave que sigue a la cámara.
        - Piel con MeshPhysicalMaterial (sheen rojizo tenue o "wrap
          lighting" sencillo); tela con sheen.
        - Cabello con alphaHash o alpha-to-coverage.
        - Forzar LOD0 a distancia de cámara cercana.
  D) RIG (por orden de preferencia)
     1. Auto-rig de Tripo por API, pidiendo esqueleto con nomenclatura
        compatible con Mixamo si la API lo ofrece. Corre antes la
        comprobación previa de rig.
     2. Auto-rigger de Mixamo: yo subo el modelo y descargo el FBX con skin
        (tarea humana de 2 minutos por personaje).
     3. AccuRIG (gratis) o Auto-Rig Pro (solo si yo lo compro).
     Validación: renderiza poses extremas (brazos arriba, sentadilla, torso
     girado, zancada) y revisa deformaciones, estiramientos y ropa
     atravesando el cuerpo. Prompt de referencia: "Verifica que los huesos
     estén alineados con las articulaciones; prueba levantar brazos, doblar
     piernas y girar el torso; corrige deformaciones, estiramientos y
     atravesamientos."

7.3 ANIMACIÓN, MOVIMIENTO NATURAL Y ROPA CON FÍSICA
  - Fuente principal: el paquete de animaciones Mixamo del Anexo A. Se
    descarga UNA sola vez y sirve para todos los humanoides, porque el
    esqueleto Mixamo es común.
  - Alternativas automatizables: retarget de Tripo por API, o la Universal
    Animation Library de Quaternius (CC0) con retarget en Blender.
  - Exporta las animaciones en un .glb compartido sin malla
    (anim_humanoide_base.glb) y cárgalas sobre cualquier personaje con el
    mismo esqueleto.
  - Reutilización entre razas de distinta altura: elimina las pistas de
    posición excepto la de Hips, y escala Hips.position por
    (altura_raza / altura_referencia).
  - Locomoción con mezcla de pesos idle↔caminar↔correr según la velocidad
    real.
  - Ajusta playbackRate = velocidad_actual / velocidad_nativa_del_clip,
    midiendo la zancada, para que NO haya foot sliding.
  - Crossfade de 0,15 a 0,25 s entre estados. El giro interpola el yaw a
    unos 720°/s, con una ligera inclinación del torso en curvas.
  - Variaciones de idle aleatorias cada 8 a 15 s.
  - La cabeza mira hacia el objetivo o el NPC (rotación procedural limitada).
  - Reacción a golpes con clip corto o capa aditiva. Muerte con clip y, en
    monstruos, disolución por shader a los 5 s.
  - Root motion: locomoción "In Place". En ataques y skills se elimina el
    desplazamiento de la raíz, porque la posición la decide el servidor.
  - ROPA Y CABELLO QUE SE MUEVEN (requisito explícito):
     - En Blender (tools\blender\add_spring_bones.py), añade cadenas de 3 a
       5 huesos a capas, faldones, túnicas, cintas, cabello largo y
       estandartes, emparentadas al pecho, la cadera o la cabeza. Pinta los
       pesos solo en esa región, o usa la pieza separada.
     - En el motor, un SpringBoneSystem propio por integración verlet con
       rigidez, arrastre, gravedad, viento y esferas de colisión en cadera,
       muslos y torso para que la tela no atraviese el cuerpo.
     - Se desactiva a distancia y en el preset Bajo.
     - Banderas y estandartes de escenario: shader de vértice con viento.
  - Equipamiento visual: los sets de armadura son mallas con skin que
    comparten el esqueleto. Las armas van en sockets de hueso: hand_r_socket,
    hand_l_socket y back_socket.

7.4 PROPS Y ESCENARIO
  - En Tripo, modo "HD Model" con modelo de IA "H3.1 – Best Quality",
    Texture ON, calidad de textura 2K (4K para los protagonistas), "Remove
    Lighting" ON, PBR ON, topología Triangle y polycount alto (unos 40.000)
    que luego se reduce con LODs.
  - MODELOS MADRE: genera pocas variantes de alta calidad y reutilízalas
    miles de veces con instancing y rotación, escala y tinte aleatorios.
    Ejemplos: roca grande T1, roca con musgo T2, arbusto T3, tocón T4, tronco
    caído T5.
  - Busca primero en bibliotecas (Poly Haven, Fab gratis, Quaternius) para
    ahorrar créditos.
  - Arquitectura: kit modular (muros, columnas, arcos, techos, escaleras,
    puertas) con la rejilla documentada. Las piezas protagonistas (fuente,
    estatua, puerta de la ciudad) se hacen en Tripo.
  - Los props nunca flotan: proyecta cada uno al suelo al colocarlo y
    alinéalo con la normal si procede.

7.5 TERRENO, VEGETACIÓN, ILUMINACIÓN Y "VIDA"
  - Escala: 1 unidad = 1 metro, eje Y hacia arriba. La zona de caza del
    vertical slice mide unos 512 x 512 m; la ciudad va en una meseta.
  - Terreno: heightmap por zona, generado con ruido más máscaras dibujadas
    (caminos, meseta, río, lago). Dividido en chunks con 3 LODs.
  - Material del terreno: shader de 4 a 8 capas PBR (hierba, tierra, camino
    empedrado, roca, musgo, arena/nieve según el reino).
    - Pesos por pendiente, altura, ruido y máscara pintada.
    - Triplanar en acantilados y mezcla por altura (height blending).
    - Normal de detalle y variación de macro-escala para que no se note el
      tiling.
  - Vegetación:
    - Hierba instanciada en GPU con viento y flexión al paso del jugador;
      densidad según el preset.
    - Flores y arbustos.
    - Árboles con viento por vértice, LODs e impostores (billboards) a
      distancia.
    - Dispersión por reglas: capa del splat, pendiente y distancia a
      caminos.
  - Detalle de suelo: piedritas, ramas, hojas y escombros instanciados;
    decals de grietas, charcos, manchas y huellas.
  - Agua: shader con color según profundidad, normales animadas, fresnel,
    espuma en bordes y flow map en ríos.
  - Cielo e iluminación:
    - HDRI de Poly Haven para la iluminación ambiental (IBL vía PMREM).
    - Sol direccional con sombras (CSM en presets altos; una sola sombra que
      sigue al jugador en móvil).
    - Niebla exponencial por altura ajustada al color del cielo.
    - LUT de color por zona y bloom moderado.
  - Para el vertical slice, fija la HORA DORADA (la más bonita). El ciclo
    día/noche llega después (P1).
  - Vida ambiental: pájaros (boids simples), mariposas, polen o polvo en
    contraluz, humo de chimeneas, antorchas con luz parpadeante, estandartes
    al viento, NPCs que caminan por rutas en la ciudad (P1) y emisores de
    sonido ambiente.

7.6 OPTIMIZACIÓN PARA WEB Y MÓVIL (tools\pipeline\optimize.mjs)
  - Con gltf-transform: dedup, prune, weld, resample de animaciones,
    cuantización, compresión EXT_meshopt_compression y simplify de
    meshoptimizer para los LODs.
  - Texturas a KTX2: ETC1S para color base y ORM, UASTC para normales.
    Genera variantes de 1024 y 2048 según el preset.
  - Valida cada .glb con gltf-validator: cero errores.
  - Genera apps\client\public\assets\manifest.json con hash, tamaño, LODs y
    dependencias. El cliente carga por manifest y por zona, con barra de
    progreso real.
  - Un solo comando, "pnpm assets:build", procesa todo lo nuevo de
    assets_src y es idempotente (no reprocesa lo que no cambió).

8.1 Concepto
  MMORPG ligero inspirado en Lineage II: combate por objetivo
  (tab-target), click-to-move en escritorio y joystick en móvil, PvE primero.
  Niveles 1-150, clases con profesiones, ciudades pacíficas (zonas seguras),
  zonas de caza por rangos de nivel, jefes, torres, botín, materiales y
  economía con NPCs.

8.2 Atributos (estilo L2)
  - Base: STR, DEX, CON, INT, WIT, MEN.
  - Recursos: HP, MP y CP (puntos de combate, absorben daño PvP primero).
  - Derivados: P.Atk, M.Atk, P.Def, M.Def, Precisión, Evasión, Crítico,
    Vel. Ataque, Vel. Lanzamiento y Velocidad.
  - Modificador de nivel de referencia: (nivel + 89) / 100.
  - Todas las fórmulas viven en packages\shared\formulas.ts con tests.

8.3 Razas (7) con bonificaciones estilo L2
  - Humano: equilibrado.
  - Elfo: DEX, velocidad y lanzamiento altos; HP bajo.
  - Elfo Oscuro: STR e INT altas, daño alto; defensa baja.
  - Orco: HP, CON y STR altos; lento lanzando.
  - Enano: CON alta; artesanía y saqueo (spoil); solo luchador.
  - Kamael: especialistas en armas (estoque, espada antigua, ballesta).
  - Ertheia: solo femenino, luchadora o maga del viento.

8.6 Objetos y economía
  - Moneda: Adena. SP para skills.
  - Grados: Sin grado (1-19), D (20-39), C (40-51), B (52-60), A (61-75),
    S (76-84), R (85-109), R+ (110-129) y Ω (130-150).
  - Rareza visual: común, poco común, raro, épico y legendario. Haz de luz
    del color de la rareza sobre el botín.
  - Equipo:
    - Armas: espada, contundente, daga, arco, lanza, puños, espadas dobles,
      bastón, estoque y ballesta.
    - Armaduras: pesada, ligera y túnica, en sets.
    - Joyería: collar, 2 pendientes y 2 anillos.
    - Joyas únicas de jefe.
  - Consumibles: Poción de Salud (menor, media y mayor), Poción de Maná,
    Elixir de CP, Pergamino de Escape (vuelve a la ciudad), Soulshot y
    Spiritshot (potencian el daño), flechas, pergaminos de encantamiento.
  - Materiales por banda de nivel (pieles, huesos, minerales, telas,
    cristales, esencias) para crafteo (Fase 12).
  - El NPC compra al 50% del precio. Teletransportes con coste en adena.
  - Encantamiento: seguro hasta +3, con riesgo hasta +16 (Fase 12).

8.7 Regeneración y muerte
  - Regeneración natural de HP, MP y CP: x2 caminando lento, x3 sentado
    (como en L2).
  - Pociones con enfriamiento compartido por tipo.
  - Fuente de sanación en ciudades.
  - Muerte: pérdida de XP configurable (por defecto 2%, nunca baja de
    nivel); reaparición en la ciudad más cercana.

8.8 Progresión
  - xp_table.json se genera con una fórmula y está documentada.
  - Ritmo objetivo (más ágil que L2, es un juego personal): 1→20 en ~1,5 h;
    20→40 en ~6 h; 40→76 en ~40 h; 76→150 es el endgame largo.
  - Penalización de XP contra monstruos más de 5 niveles por debajo.
  - Color del nombre del objetivo según la diferencia de nivel, estilo L2.

8.9 NPCs de cada ciudad
  - Guardián de Portales (Gatekeeper): teletransporte entre ciudades y
    zonas de caza.
  - Tienda de Víveres (Grocery): pociones, pergaminos, shots y flechas.
    Compra y venta.
  - Comerciante de Armas y Comerciante de Armaduras.
  - Tienda Mágica: libros de hechizos y catalizadores.
  - Almacén (Warehouse).
  - Maestro de Clase: cambio de profesión y aprendizaje de skills.
  - Herrero: cristalizar, encantar y fabricar (Fase 12).
  - Sacerdotisa del templo: buffs de novato hasta nv40, como el Newbie
    Helper de L2.
  - Guardias y ciudadanos ambientales.
  - Diálogo con retrato, texto con estilo, botones grandes para el tacto y
    cámara de diálogo cercana.

  3. SELVA DE IXMARAL. Ciudad: Ixtalá (en las copas y en un templo).

     - Nv50: Quetzar, la Serpiente Emplumada de Jade.
     - Nv60: Oruk-Tal, el Chamán Lagarto.
  4. DUNAS DE KHARZIM. Ciudad: Kharzim (oasis).
     Bioma: desierto, cañones, tumbas, tormentas de arena. Niveles 60-85.

     - Nv80: Anuketh, el Faraón Sin Rostro.
  5. TIERRAS HELADAS DE NORDHRIM. Ciudad: Fortaleza Nordhrim.

  6. VOLCÁN IGNAROTH. Ciudad: Forjaroja (ciudad-forja enana).

################################################################################
## 9. ARQUITECTURA TÉCNICA
################################################################################

9.1 Red
  - Una sala Colyseus por zona. El teletransporte sale de una sala y entra a
    otra, con pantalla de carga.
  - Tick del servidor a 20 Hz. IA a 5 Hz en reposo y 20 Hz en combate.
  - Gestión de interés: solo se envían las entidades a menos de 80 m.
  - El cliente envía INTENCIONES:
      moveTo(x,z) | moveDir(vec) | stop | target(id) | attack(id)
      useSkill(id, target) | toggleSkill(id) | sit | pickup(dropId)
      npcInteract(npcId) | shopBuy / shopSell | learnSkill
      teleport(destId) | useItem | equip / unequip | chat | gm(cmd, args)
  - Todos los mensajes se validan con zod.
  - El cliente PREDICE su propio movimiento sobre la navmesh y reconcilia
    con el servidor. Las demás entidades se interpolan con un búfer de
    unos 100 ms.
  - El combate se resuelve en el servidor: valida rango, línea de visión,
    reuso, MP y estado. El servidor emite eventos (skillStart, skillHit,
    damage, death, levelUp, drop) que el cliente usa para animaciones, VFX,
    SFX y números flotantes.

9.2 Navegación
  - Cada zona exporta su colisión simplificada. tools\pipeline\navmesh.mjs
    genera la navmesh con recast-navigation; servidor y cliente usan el
    mismo archivo.
  - Con navmesh no hace falta física de cuerpos rígidos: L2 no tenía salto
    de plataformas. Puede haber un salto cosmético.

9.3 Persistencia
  - El estado del personaje vive en memoria del servidor. Se guarda en
    transacción cada 60 s y también en eventos clave: subir de nivel,
    compra o venta, equipar, cambiar de zona, desconexión y apagado (con
    manejador SIGINT).
  - Esquema inicial en el Anexo D.
  - Conexión mssql: server localhost (o localhost\SQLEXPRESS), base IAJuego,
    con options { encrypt: true, trustServerCertificate: true }.
  - Si la instancia es con nombre y no conecta, usa el puerto TCP fijo y
    documenta cómo se habilitó.

9.4 Seguridad mínima
  - Contraseñas con argon2id.
  - Límite de intentos de login.
  - JWT de sesión corta.
  - Consultas siempre parametrizadas.
  - CORS restringido.
  - .env fuera de git.
  - El puerto 1433 de SQL NUNCA se expone a internet.
  - La app usa el login iajuego_app con permisos de lectura y escritura;
    las migraciones se corren con sa.

9.5 Despliegue local y teléfono (documéntalo en docs\JUGAR_EN_TELEFONO.md)
  - "pnpm build" genera el cliente. El servidor sirve el build y los
    websockets en un único puerto (2567): una sola URL.
  - Desarrollo: Vite en 5173 con proxy al servidor.
  - LAN: usa la IP local del PC y añade una regla en el Firewall de Windows
    solo para ese puerto.
  - Fuera de casa, con HTTPS (necesario para PWA y service worker):
    - Opción privada recomendada: Tailscale en el PC y el teléfono, con
      "tailscale serve" para tener HTTPS.
    - Para compartir temporalmente: Cloudflare Quick Tunnel
      (cloudflared tunnel --url http://localhost:2567).
  - El servidor corre como proceso persistente con pm2 o como servicio de
    Windows (NSSM). Hay script de arranque y de parada.

9.6 Pantalla completa y móvil
  - Botón de pantalla completa en login, HUD y ajustes. Usa la Fullscreen
    API con navigationUI "hide" y screen.orientation.lock("landscape") en
    Android.
  - Manifest PWA con display "fullscreen" y orientation "landscape".
  - En iPhone la Fullscreen API no existe para páginas. Muestra una guía
    para "Añadir a pantalla de inicio" (modo standalone).
  - Respeta las safe-area-insets. Botones táctiles de 44 px como mínimo.

CREATE TABLE dbo.schema_migrations (
  version     VARCHAR(64) PRIMARY KEY,
  applied_at  DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME()
);
CREATE TABLE dbo.accounts (
  id             INT IDENTITY(1,1) PRIMARY KEY,
  username       NVARCHAR(32)  NOT NULL UNIQUE,
  password_hash  NVARCHAR(255) NOT NULL,
  role           TINYINT       NOT NULL DEFAULT 0,      -- 0 jugador, 9 GM
  banned         BIT           NOT NULL DEFAULT 0,
  created_at     DATETIME2     NOT NULL DEFAULT SYSUTCDATETIME(),
  last_login_at  DATETIME2     NULL
);
CREATE TABLE dbo.characters (
  id            INT IDENTITY(1,1) PRIMARY KEY,
  account_id    INT NOT NULL REFERENCES dbo.accounts(id),
  name          NVARCHAR(24) NOT NULL UNIQUE,
  race          VARCHAR(16)  NOT NULL,
  gender        CHAR(1)      NOT NULL,
  base_class    VARCHAR(32)  NOT NULL,
  class_id      VARCHAR(32)  NOT NULL,
  level         SMALLINT     NOT NULL DEFAULT 1,
  exp           BIGINT       NOT NULL DEFAULT 0,
  sp            BIGINT       NOT NULL DEFAULT 0,
  hp INT NOT NULL, mp INT NOT NULL, cp INT NOT NULL,
  adena         BIGINT       NOT NULL DEFAULT 0,
  zone_id       VARCHAR(32)  NOT NULL,
  pos_x FLOAT NOT NULL, pos_y FLOAT NOT NULL, pos_z FLOAT NOT NULL,
  heading       FLOAT        NOT NULL DEFAULT 0,
  appearance    NVARCHAR(MAX) NULL,                     -- JSON
  gm_god        BIT          NOT NULL DEFAULT 0,
  deleted       BIT          NOT NULL DEFAULT 0,
  created_at    DATETIME2    NOT NULL DEFAULT SYSUTCDATETIME(),
  last_save_at  DATETIME2    NULL
);
CREATE TABLE dbo.character_skills (
  character_id  INT NOT NULL REFERENCES dbo.characters(id),
  skill_id      VARCHAR(48) NOT NULL,
  skill_level   SMALLINT    NOT NULL,
  PRIMARY KEY (character_id, skill_id)
);
CREATE TABLE dbo.items (
  id            BIGINT IDENTITY(1,1) PRIMARY KEY,
  owner_id      INT NOT NULL REFERENCES dbo.characters(id),
  item_def_id   VARCHAR(48) NOT NULL,
  count         BIGINT      NOT NULL DEFAULT 1,
  enchant       SMALLINT    NOT NULL DEFAULT 0,
  location      VARCHAR(12) NOT NULL,     -- INVENTORY | PAPERDOLL | WAREHOUSE
  slot          VARCHAR(16) NULL,         -- HEAD CHEST LEGS GLOVES FEET RHAND
                                          -- LHAND NECK EAR1 EAR2 FINGER1 FINGER2
  created_at    DATETIME2   NOT NULL DEFAULT SYSUTCDATETIME()
);
CREATE INDEX IX_items_owner ON dbo.items(owner_id, location);
CREATE TABLE dbo.shortcuts (
  character_id  INT NOT NULL REFERENCES dbo.characters(id),
  page TINYINT NOT NULL, slot TINYINT NOT NULL,
  type          VARCHAR(8)  NOT NULL,     -- SKILL | ITEM | ACTION
  ref_id        VARCHAR(48) NOT NULL,
  PRIMARY KEY (character_id, page, slot)
);
CREATE TABLE dbo.character_buffs (
  character_id  INT NOT NULL REFERENCES dbo.characters(id),
  skill_id      VARCHAR(48) NOT NULL,
  skill_level   SMALLINT    NOT NULL,
  remaining_ms  INT         NOT NULL,
  PRIMARY KEY (character_id, skill_id)
);
CREATE TABLE dbo.boss_status (
  boss_id       VARCHAR(48) PRIMARY KEY,
  state         VARCHAR(8)  NOT NULL,     -- ALIVE | DEAD
  respawn_at    DATETIME2   NULL
);
CREATE TABLE dbo.gm_audit (
  id            BIGINT IDENTITY(1,1) PRIMARY KEY,
  account_id    INT NOT NULL,
  character_id  INT NULL,
  command       NVARCHAR(64)  NOT NULL,
  args          NVARCHAR(400) NULL,
  at            DATETIME2     NOT NULL DEFAULT SYSUTCDATETIME()
);
